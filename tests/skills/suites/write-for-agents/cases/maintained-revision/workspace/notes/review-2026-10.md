# Review of the assistant's checks, October 2026 (records keeper)

Over the last quarter I went back through the check outputs under
`checks/`. First I compared the file names with the readings files changed
in each session: two sessions had changed files with no check saved. Then I
reran `gaugetool check` on those two files myself: both exit 2, with gaps
in the first week of July. Then I looked for the cause and found that the
readers' July cards had arrived late and been entered in a separate session
that never ran the check.

What changes:

- The check runs once per session, before the session ends, on every
  readings file the session changed, instead of file by file as the
  assistant goes. One output file per session under `checks/`, named
  `<date>.txt`.
- Exception: a file the session changed only to add or remove a `?` flag
  needs no check, because the flag column is outside what `gaugetool check`
  validates.
- A file whose check exits 2 is reported to the coordinator in the
  session's report with its gaps listed. The assistant does not fill gaps.

Everything else in the standing instructions stays as it is. I will speak
to the readers about the late cards myself; that is not the assistant's
business.
